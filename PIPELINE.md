# Ximera TeX→HTML Pipeline: Complete Process Documentation

## Overview

Xake is a build orchestrator. It does **not** do the actual TeX conversion itself — it calls `pdflatex` and `htlatex` (from TeX4ht) in sequence, then post-processes the resulting HTML.

---

## Prerequisites (External Tools Required)

| Tool | Purpose |
|------|---------|
| `pdflatex` | First-pass LaTeX compilation |
| `htlatex` | TeX→HTML conversion (from the `tex4ht` package) |
| `sage` | Optional: execute SageMath embedded computations |
| `kpsewhich` | Verify `ximera.cls` is installed |
| `ximera.cls` | LaTeX document class — built from `.dtx` sources in `ximera-core/latex/` via `npm run build:latex` |

Install TeX4ht via your TeX distribution: `tlmgr install tex4ht`

## Step-by-Step Compilation for a Single `.tex` File

Given `path/to/myfile.tex`:

### Step 1 — Clean temporary files

Delete any existing files with these extensions in the same directory as the `.tex` file:
```
.aux .4ct .4tc .oc .md5 .dpth .out .jax .idv .lg .tmp .xref .log .auxlock .dvi .pdf .scmd .sout
```

### Step 2 — First `pdflatex` pass

Run in the **same directory** as the `.tex` file:
```bash
cd path/to/
pdflatex -file-line-error -shell-escape \
  "\PassOptionsToClass{tikzexport}{ximera}\PassOptionsToClass{xake}{ximera}\PassOptionsToClass{xake}{xourse}\nonstopmode\input{myfile.tex}"
```

Key points:
- Run in the file's directory (not the repo root)
- Pass only the **basename** (not full path) to `\input{}`
- The class options `tikzexport` and `xake` trigger special behavior in `ximera.cls`
- `\nonstopmode` keeps going on errors

### Step 3 — SageMath (conditional)

If `myfile.sagetex.sage` was generated by Step 2:
```bash
sage myfile.sagetex.sage
```
Then run **Step 2 again** to incorporate the results.

### Step 4 — `htlatex` pass (the actual HTML conversion)

```bash
cd path/to/
htlatex myfile.tex "ximera,charset=utf-8,-css" " -cunihtf -utf8" "" "--interaction=nonstopmode -shell-escape -file-line-error"
```

Arguments to `htlatex`:
1. `myfile.tex` — input file (basename)
2. `"ximera,charset=utf-8,-css"` — htlatex config: use `ximera` config, UTF-8 charset, no separate CSS
3. `" -cunihtf -utf8"` — tex4ht options: Unicode handling
4. `""` — t4ht options (empty)
5. `"--interaction=nonstopmode -shell-escape -file-line-error"` — passed to latex

This produces `myfile.html` (and possibly `.css`, `.png`, `.svg` files).

The `ximera` htlatex configuration must exist on the TeX path — it is part of `ximera.cls`.

### Step 5 — HTML post-processing

After `htlatex` runs, the generated HTML is modified in-place:

**5a. Remove empty paragraphs**
```
Remove all <p></p> elements from the DOM
```

**5b. Inject dependency metadata**

Parse the `.tex` file for all `\input{}`, `\activity{}`, `\include{}`, `\includeonly{}` references. For each dependency file (plus the `.tex` file itself), compute its SHA1 hash and inject into `<head>`:
```html
<meta name="dependency" content="SHA1HASH relative/path/to/file.tex">
```

This is how xake detects whether recompilation is needed on subsequent runs.

**5c. Xourse files only** (files with `\documentclass{xourse}`)

Detect via `<meta name="description" content="xourse">` in the HTML:
1. Remove all `<a id="...">` anchor tags (htlatex inserts these spuriously)
2. For each `<a class="activity" href="activity.tex">`:
   - Normalize the href to be relative to repo root, without `.tex` extension
   - Read the compiled `activity.html` and extract its `<title>` and `<div class="abstract">`
   - Inject `<h2>TITLE</h2><h3>ABSTRACT</h3>` inside the activity link

## File Eligibility Rules

A `.tex` file is compiled only if:
1. It has a `.tex` extension
2. It contains `\begin{document}` (after stripping comments and whitespace)
3. It is committed to the git repository (and matches the committed version)

---

## Compilation Order (for `bake` / batch mode)

When compiling an entire repository:

1. **Find all eligible `.tex` files** (see rules above)
2. **Determine which are "dirty"** — check if the `.html` exists and its embedded `<meta name="dependency">` hashes still match the current files. Fall back to mtime comparison if no dependency metadata exists.
3. **Propagate dirtiness** — if file A `\input`s file B, and B is dirty, then A is also dirty.
4. **Topological sort** — build a dependency graph so that if A depends on B, B compiles first.
5. **Parallel workers** — compile dirty files with N parallel workers (default: 2), respecting dependency order.

---

## Publication Artifacts

After compilation, for each `.tex` file the outputs published are:
- `myfile.html` — only if `<meta name="ximera">` tag is present (set by `ximera.cls` via htlatex)
- All `<img src="...">` referenced local images (`.png`, `.svg`, and for `.svg` also the `.png` variant)
- `metadata.json` at the repo root (labels map, xourse metadata, GitHub info)

## GitHub Actions Equivalent

To replicate this in CI without Go/xake:

```yaml
- name: Install TeX Live
  run: sudo apt-get install -y texlive-full

- name: Build ximera-core LaTeX class
  run: |
    cd ximera-core
    npm install
    npm run build:latex     # populates latex/dist/{ximera,xourse}.{cls,4ht}, ximera.cfg
    # tex4npm's stage.js symlinks these into each course's .tex4npm/texmf/
    # at build time; no need to install into ~/texmf/.

- name: Compile each .tex file
  run: |
    # For each committed .tex file containing \begin{document}:
    for f in $(git ls-files '*.tex'); do
      if grep -q '\\begin{document}' "$f"; then
        dir=$(dirname "$f")
        base=$(basename "$f")
        stem="${base%.tex}"

        # Clean
        cd "$dir"
        rm -f "$stem".{aux,4ct,4tc,oc,md5,dpth,out,jax,idv,lg,tmp,xref,log,auxlock,dvi,pdf}

        # pdflatex pass 1
        pdflatex -file-line-error -shell-escape \
          "\PassOptionsToClass{tikzexport}{ximera}\PassOptionsToClass{xake}{ximera}\PassOptionsToClass{xake}{xourse}\nonstopmode\input{$stem.tex}"

        # SageMath (if needed)
        [ -f "$stem.sagetex.sage" ] && sage "$stem.sagetex.sage"

        # pdflatex pass 2 (always run)
        pdflatex -file-line-error -shell-escape \
          "\PassOptionsToClass{tikzexport}{ximera}\PassOptionsToClass{xake}{ximera}\PassOptionsToClass{xake}{xourse}\nonstopmode\input{$stem.tex}"

        # htlatex (TeX → HTML)
        htlatex "$stem.tex" "ximera,charset=utf-8,-css" " -cunihtf -utf8" "" \
          "--interaction=nonstopmode -shell-escape -file-line-error"

        cd -
      fi
    done
```

The HTML post-processing (dependency metadata injection, xourse link enrichment) is the Go-specific part — you would need to reimplement that in Python/Node/shell if you want it. However, the raw `.html` files from `htlatex` are functional without that step; the metadata is only used by xake's incremental rebuild cache and by the Ximera server's label anchoring system.

---

## Key Dependency

The `ximera` htlatex configuration (which tells tex4ht how to convert Ximera-specific macros to HTML) lives inside `ximera.cls`. The `ximera,charset=utf-8,-css` argument to `htlatex` references this config. Without `ximera.cls` installed, htlatex will fall back to a generic conversion that won't correctly handle Ximera-specific environments like `\begin{problem}`, `\begin{exercise}`, interactive elements, etc.
